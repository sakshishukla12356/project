### 2. Rate Limiting Added ✅

#### New File: [rate_limit.py](file:///c:/Users/Sanskruti%20Ingle/Desktop/CloudCost/project/backend/middleware/rate_limit.py)

Sliding-window counter with tiered rate limits per route category:

| Tier | Routes | Limit | Ban Policy |
|------|--------|-------|------------|
| **AUTH** | `/auth/login`, `/auth/signup`, `/auth/reset` | 5 req / 60s | Auto-ban after 10 consecutive 429s (10 min) |
| **AI** | `/ai/*` (chatbot) | 10 req / 60s | Auto-ban after 30 consecutive 429s (5 min) |
| **CLOUD_WRITE** | `/cloud/stop`, `/cloud/start` | 10 req / 60s | No auto-ban |
| **PUBLIC** | All other routes | 60 req / 60s | No auto-ban |
| **HEALTH** | `/health`, `/` | 120 req / 60s | No auto-ban |

#### How It Works

```mermaid
flowchart TD
    A["Incoming Request"] --> B["Extract Client IP<br/>(X-Forwarded-For or direct)"]
    B --> C["Match Path → Tier"]
    C --> D{"IP Banned?"}
    D -->|Yes| E["429 + Retry-After header"]
    D -->|No| F{"Within Window Limit?"}
    F -->|No| G["Increment 429 counter"]
    G --> H{"Exceeded ban_after?"}
    H -->|Yes| I["Temp-ban IP"]
    H -->|No| E
    F -->|Yes| J["✅ Allow + set rate-limit headers"]

    style E fill:#ff6b6b,color:#fff
    style I fill:#ff6b6b,color:#fff
    style J fill:#51cf66,color:#fff
```

#### Integration Points

- **Global middleware** in [main.py](file:///c:/Users/Sanskruti%20Ingle/Desktop/CloudCost/project/backend/main.py#L84-L86) — catches every request
- **Per-route dependency** on [auth.py](file:///c:/Users/Sanskruti%20Ingle/Desktop/CloudCost/project/backend/routers/auth.py) (login + signup) — defense in depth
- **Per-route dependency** on [chatbot.py](file:///c:/Users/Sanskruti%20Ingle/Desktop/CloudCost/project/backend/routers/chatbot.py) — protects expensive AI calls

#### Response on Rate Limit (429)

```json
{
  "detail": {
    "error": "Too many requests. Please slow down.",
    "tier": "auth",
    "retry_after": 47,
    "banned": false
  }
}
```

Headers returned:
```
Retry-After: 47
X-RateLimit-Limit: 5
X-RateLimit-Remaining: 0
X-RateLimit-Reset: 1714924800
```

### Secrets Management

| Practice | Status |

### Deployment Recommendations

| Platform | How to Set Secrets |
|----------|--------------------|
| **Vercel** | Dashboard → Project → Settings → Environment Variables |
| **Render** | Dashboard → Service → Environment → Secret Files or Env Groups |
| **Railway** | Dashboard → Project → Variables (supports `.env` file upload) |
| **Docker** | `docker run --env-file .env` or `docker-compose.yml` with `env_file:` |
| **AWS ECS/EKS** | AWS Secrets Manager + task definition `secrets` block |
| **Azure** | Azure Key Vault + managed identity |

> 1. Go to **Azure Portal → App Registrations → Your App → Certificates & Secrets**
> 2. Delete the old secret
> 3. Create a new one
> 4. Update your local `.env` with the new value
